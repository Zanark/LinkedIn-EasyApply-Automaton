# Contributor and agent entry point

Read [the developer guide](docs/development/developer_guide.md) and
[the tracking adoption contract](docs/development/github-tracking.md) before changing workstreams.

Use [the repository layout](docs/development/repository-layout.md) and
[documentation index](docs/README.md) for current paths. Keep private runtime
folders, historical workstreams and published release bundles in place.

The canonical work inventory is [`todo/00_INDEX.todo`](todo/00_INDEX.todo).
Preserve the existing lowercase directory. Actual workstreams use numbered
`.todo` files, a stable `lea-NN` identity and all eight required fields.
The index, perpetual ledger and legacy records are not additional workstreams.

The repository is public. Review every proposed payload semantically; never
mirror raw conversations, applicant values, private continuity or runtime data.
`PUBLIC_SAFE_PROJECTION` is a reviewed publication declaration, not a sanitizer.
The original `todo/TODO.md` is excluded from synchronization; do not copy it
wholesale into a new tracked/public document or issue.

The [public project handoff](.agent-context/public/README.md) contains reviewed
engineering notes, not private session continuity. Only its four named Markdown
files are allowlisted. Keep private root files, social history and new/unreviewed
context files ignored; never force-add the context directory or copy a private
store into that projection.

After an authorized new workstream, description/evidence update, completion,
reopening, cancellation or supersession, preview the configured synchronizer.
Apply only within the current task's remote-write authority, then verify issue,
Project membership/status and the persistent backlink. Managed human edits
are conflicts, not permission to reset the baseline. Do not delete remote work
because a local file disappears.

Do not conflate tests with live qualification, human acceptance or publication.
Preserve unrelated dirty work. Commits/pushes and automation activation need
separate authority; before an authorized commit verify effective author and
committer are the repository-local Zanark identity. Keep required session trailers.
There is no activated background tracking service or tracking Actions workflow.
The Windows release workflow is separate and does not synchronize workstreams.
